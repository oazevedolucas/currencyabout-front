## Deviations / fixes applied during Task 5

### Rule 3: vite-react-ssg + react-router-dom v7 hard incompatibility

vite-react-ssg 0.9.0's RemixAdapter dynamically
`import('react-router-dom/server.js')` to pull `StaticRouterProvider`,
`createStaticHandler`, and `createStaticRouter`. In react-router-dom v6
those symbols lived at the `./server.js` subpath; in v7 they were unified
into the main entry and the subpath was dropped from the exports map.

Plan said: do not downgrade react-router-dom. Fix applied:
`scripts/patch-vite-react-ssg.mjs` (run via `postinstall`) adds a
`./server.js` re-export to `react-router-dom`'s exports field that
aliases the main entry. v7's main exports all three symbols, so this is
a true alias rather than a shim. Idempotent and safe to re-run.

### Rule 3: react-helmet-async v3 + React 19 SSR-context not populated

react-helmet-async ^3.0.0 on React 19 does NOT populate
`helmetContext.helmet` — by design, because React 19 hoists `<title>`,
`<meta>`, `<link>` elements natively. But vite-react-ssg's
`extractHelmet()` reads from `helmetContext.helmet`, so it sees nothing
and emits no per-route head tags. Meanwhile the Helmet-rendered tags
land inside `<div id="root">` because the plugin's renderToPipeableStream
output is sliced and inserted into the template's `<div id="root">` shell
without giving React 19 a chance to hoist them out.

Fix applied: `vite.config.js`'s `onPageRendered` hook post-processes the
HTML — it extracts the leading `<title>`, `<meta>`, `<link>` block that
SeoHead emits at the top of `#root`, strips the template's home-page
conflict tags from `<head>`, and re-injects the per-route block just
before `</head>`. Self-contained in our project, no node_modules
modifications.

### Rule 3: useExchangeRates loading state caused skeleton-only SSR

`useExchangeRates`'s initial `loading: true` meant HomePage and
CurrencyPairPage's `if (converter.loading) return <skeleton />` early
return fired at SSR time and shipped a skeleton-only HTML. The intro
paragraph, FAQ, ArticleSchema, BreadcrumbSchema, body copy — all the
content non-rendering crawlers care about — was absent.

Fix applied: `loading` now starts `false`, and the effect no longer flips
it to `true` at the start of the fetch. The page renders its full body
immediately on both SSR and client (with rate values gracefully degrading
to `0.0000` until the post-mount fetch resolves and the rate-bearing
nodes update in place). React's reconciliation handles the in-place
update without unmounting the editorial content.

### Rule 1: vite.config.js ssgOptions key name

Plan specified `format: 'directory'` to produce `dist/<route>/index.html`.
vite-react-ssg's actual API uses `dirStyle: 'nested'` for that; `format`
only accepts `'esm' | 'cjs'` (build output format). Fixed to use the
correct key — output layout is exactly what the plan intended.
