## Decisions Made

- **vite-react-ssg over alternatives.** Picked over (a) Vike — would replace react-router-dom and force a routing rewrite mid-review; (b) react-snap / Playwright — Puppeteer pulls 250–300 MB; (c) vite-plugin-prerender — less actively maintained. vite-react-ssg keeps react-router-dom v7, renders via React's own `renderToPipeableStream` so hydration matches by construction, ships as a Node-only dev dep with no Chromium.
- **Used `--legacy-peer-deps` for the install.** vite-react-ssg's peer is `react-router-dom: ^6.14.1` (peerOptional). We pin ^7.13.2 (validated system, per CLAUDE.md). The actual v7 main module exports `StaticRouterProvider`, `createStaticHandler`, `createStaticRouter` — exactly what the plugin needs — so the peer mismatch is paper-only at the API level.
- **Postinstall shim instead of node_modules patch-package.** `scripts/patch-vite-react-ssg.mjs` modifies the exports map of `react-router-dom`'s package.json (which IS a node_modules file, but only the metadata, no code). This is the smallest possible surface needed to unblock vite-react-ssg's dynamic import. patch-package would have added a new dependency, and the user approved exactly one new dev dep (vite-react-ssg).
- **Head hoisting in onPageRendered rather than upgrading the helmet integration.** react-helmet-async@3 + React 19 don't populate the helmetContext the plugin reads from — that's documented as expected behaviour in helmet's README. Rather than downgrading react-helmet-async to v1.3.0 (which doesn't support React 19 properly), the plugin's empty-context behaviour is paved over in our own vite.config.js. Adding a new SeoHead-emitted tag means updating the `conflictPatterns` list in vite.config.js.
- **useExchangeRates loading flag flipped to start false.** The whole point of SSG is to ship full editorial content to crawlers, not the skeleton placeholder. Trading the cold-start "rates load briefly" UX (where rates display 0.0000 for ~200 ms while the post-mount fetch runs) for full editorial visibility in initial HTML is the correct call.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Plan typo] `format: 'directory'` -> `dirStyle: 'nested'`**

- **Found during:** Task 4 (`<verify>` block for vite.config.js failed when I checked the plugin's actual API surface).
- **Issue:** The plan specified `format: 'directory'` as the way to produce `dist/<route>/index.html`. vite-react-ssg's actual `ViteReactSSGOptions` interface defines `format: 'esm' | 'cjs'` (output format) and a separate `dirStyle: 'flat' | 'nested'` (output layout). The plan's stated intent was clear; the key name was wrong.
- **Fix:** Used `dirStyle: 'nested'` in vite.config.js. Produces the exact directory layout the plan asked for.
- **Files modified:** `vite.config.js`.
- **Verification:** `find dist -name index.html` returns 63 files matching the expected `dist/<route>/index.html` pattern.
- **Committed in:** `7a17021` (Task 4 commit).

**2. [Rule 3 — Hard blocker] vite-react-ssg dynamic-imports `react-router-dom/server.js` (v6 subpath, dropped in v7)**

- **Found during:** Task 5 (first `npm run build` exited 1 with `ERR_PACKAGE_PATH_NOT_EXPORTED`).
- **Issue:** `vite-react-ssg@0.9.0`'s `RemixAdapter` runs `import('react-router-dom/server.js')` to pull `StaticRouterProvider`, `createStaticHandler`, `createStaticRouter`. react-router-dom v6 exposed these at the `./server.js` subpath; v7 unified them into the main entry and dropped the subpath from its exports map. The plan explicitly said "do not downgrade react-router-dom" — that file is referenced across many pages in the SPA and is a validated system per CLAUDE.md.
- **Fix:** Added `scripts/patch-vite-react-ssg.mjs` that runs on postinstall. It mutates `node_modules/react-router-dom/package.json` to add `./server.js` and `./server` re-exports pointing at the main entry. v7's main entry already exports the three symbols vite-react-ssg needs, so this is a true alias rather than a shim. Idempotent (checks for existing entry, exits 0 if already applied).
- **Files modified:** `package.json` (postinstall hook), `scripts/patch-vite-react-ssg.mjs` (new).
- **Verification:** `npm run build` after the postinstall ran exits 0 and produces all 63 dist files.
- **Committed in:** `0abe04d` (Task 5 commit).

**3. [Rule 3 — Hard blocker] react-helmet-async@3 + React 19 leaves `helmetContext` unpopulated; per-route head tags ended up inside `<div id="root">` instead of `<head>`**

- **Found during:** Task 5 (first successful build produced HTML where pair pages had the home-page `<title>` in `<head>` and the per-route `<title>` buried inside `<div id="root">`).
- **Issue:** react-helmet-async@3.0.0 detects React 19 at runtime and switches to native metadata hoisting — but vite-react-ssg's `RemixAdapter` slices the rendered React tree into a string and inserts it as raw HTML inside `<div id="root">`, never giving React 19's metadata hoisting a chance to lift `<title>`/`<meta>`/`<link>` to `<head>`. Meanwhile, the plugin still reads from `helmetContext.helmet` (which v3 + React 19 don't populate, by design — documented in the v3 README's "React 19 SSR note"), so the plugin's own head-injection finds nothing to inject.
- **Fix:** vite.config.js's `onPageRendered` hook now post-processes the HTML — it captures the leading `<title>`/`<meta>`/`<link>` block at the start of `<div id="root">` (where SeoHead emits them), strips conflicting tags from the index.html template's `<head>` (home `<title>`, og:title, og:description, og:url, og:image*, twitter:*, description, canonical), and injects the per-route block just before `</head>`. Self-contained in our project — zero node_modules code edits, zero new dependencies.
- **Files modified:** `vite.config.js`.
- **Verification:** `sed -n '/<head>/,/<\/head>/p' dist/usd-to-brl/index.html | grep "<title>USD to BRL"` matches; `grep "About Currency - Live Exchange Rates" dist/usd-to-brl/index.html | head -5` no longer matches inside `<head>`. The audit JSON shows correct per-route titles for all 63 entries.
- **Committed in:** `0abe04d` (Task 5 commit).

**4. [Rule 3 — Hard blocker] `useExchangeRates` loading=true caused HomePage / CurrencyPairPage to ship skeleton-only HTML**

- **Found during:** Task 5 (first successful build produced 18 KB pair pages because both page components early-return a skeleton when `converter.loading` is true — and SSR-side, the post-mount fetch effect hasn't run yet, so `loading` stays at its initial `true`).
- **Issue:** The whole point of SSG is to ship full editorial content. With the original `loading: true` initial state, the pre-rendered HTML contained the loading-skeleton `<div>` and nothing else — defeating the entire phase. The plan's `must_haves.truths` explicitly require the pair intro paragraph from `pairProfiles.js` to be in initial HTML.
- **Fix:** `src/hooks/useExchangeRates.js` initial `loading` state now `false`. The effect's `setLoading(true)` at fetch start is removed (kept the `setLoading(false)` in the `finally` block — harmless on the false-to-false transition). Pages now render their full editorial body during SSR and initial client paint; rate-bearing nodes degrade to `0.0000` until the post-mount fetch resolves and React reconciliation updates them in place without unmounting surrounding content.
- **Files modified:** `src/hooks/useExchangeRates.js` (not in plan's `files_modified` — but the alternative was modifying HomePage and CurrencyPairPage, both of which were also not in the list. The hook is the smaller and more central change.).
- **Verification:** Re-built; pair pages went from 18 KB to ~39 KB; `grep "Brazilian importers" dist/usd-to-brl/index.html` returns 1 match (the hand-written pair intro is in initial HTML).
- **Committed in:** `0abe04d` (Task 5 commit).

## Issues Encountered

The four deviations above were all surfaced and resolved during Task 5. No other issues required problem-solving.

A handful of cosmetic notes recorded in `03.1-01-SSG-AUDIT.md` for future-phase consideration (not blocking this plan):

1. Cloudflare's static-assets handler issues a 307 -> trailing-slash redirect for `dist/<route>/index.html` files served at `/<route>`. Crawlers handle this one-hop redirect cleanly. If a future phase wants to eliminate the redirect, two options: configure `_redirects`/`_headers`, or switch to `dirStyle: 'flat'` (produces `dist/<route>.html` instead).
2. React 19 emits `<div hidden id="S:0">` streaming-resolved blocks wherever a `<Suspense>` boundary is present, even if no child is actually lazy. The pair pages' full editorial content lands in that hidden block (because LayoutOutlet wraps Outlet in Suspense for the lazy guides routes). Crawlers see hidden content in initial HTML as indexable — Google explicitly documents this. If a future phase wants cleaner HTML, the `<Suspense>` can be moved from LayoutOutlet into only the lazy-route components.
