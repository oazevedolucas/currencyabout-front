Add build-time pre-rendering so every indexable URL in public/sitemap.xml
ships per-route HTML — correct <title>, <meta description>, <link rel=canonical>,
Open Graph tags, JSON-LD, and the actual rendered editorial content — to
non-rendering crawlers (AdSense reviewer crawler, Bing first-pass, social card
scrapers, GPTBot, ClaudeBot, PerplexityBot). The SPA hydrates on top of the
pre-rendered HTML with no console hydration warnings on the test trio
(/, /guides/currency-conversion-fees-compared, /usd-to-brl).

Purpose: SEO audit C-1 is the single most damaging signal driving the
"low value content" AdSense recusal of 2026-05-17. Every URL currently
serves byte-identical home-page metadata in initial HTML; 16 hand-written
guides, 21 currency profiles, methodology page, AI-disclosure, BylineMeta
Person schema, and 38 hand-written pair intros are completely invisible to
any crawler that does not execute JavaScript. This phase moves all of that
content into initial HTML for every indexable route.

| Boundary | Description |
|----------|-------------|
| build host → dist | A compromised or poisoned `vite-react-ssg` build step could inject content into every pre-rendered HTML. The build runs on the developer machine (no CI yet), so the boundary is between the developer's npm install and the dist output. |
| crawler → pre-rendered HTML | Non-rendering crawlers (AdSense, Bing first-pass, social scrapers, AI crawlers) consume initial HTML directly. Trust boundary is the per-route metadata correctness — wrong metadata is harmful (e.g. accidental noindex baked into an indexable route). |
| client browser → hydration | Pre-rendered HTML and client bundle must agree on initial state. A hydration mismatch is a correctness/UX bug, not a security threat — but is in scope for this phase's risk register. |
