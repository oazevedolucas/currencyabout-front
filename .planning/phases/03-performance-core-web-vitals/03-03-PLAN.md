<threat_model>
This plan edits the static HTML head and adds a Cloudflare static-asset headers file. It does not touch network code, storage, the converter, or any consent surface. ASVS L1 review:

- **Font load failure on noscript / privacy-blocked browsers:** the `media="print" onload="this.media='all'"` pattern degrades gracefully — if `onload` never fires (CSP blocks inline `onload`, JS disabled), the stylesheet stays at print-media scope and the fallback fonts in the existing CSS (`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`) render. The `<noscript>` wrapper picks up JS-disabled crawlers explicitly. Mitigation: T1 acceptance criteria require both the swapped `<link>` and the `<noscript>` fallback to be present; T3 grep checks confirm both.
- **CSP inline `onload` attribute:** the current site has no `Content-Security-Policy` header (verified via `grep -ri "Content-Security-Policy" .` returning no matches in this repo and `wrangler.jsonc` carrying no header config that would emit one). The Cloudflare Workers static-assets default response also does not inject a CSP. The inline `onload="this.media='all'"` is therefore not blocked. Mitigation: T1 read_first includes a grep audit confirming no CSP header is being emitted by the codebase. If a CSP is later added in another phase, the inline `onload` would need to move to an external script — that is a future-phase concern.
- **AdSense reviewer regression on visible typography:** the largest risk in this plan. If Inter never loads (e.g. browser misinterprets `media="print"`), the page renders in system fallback fonts — visibly different to a returning reviewer mid-review. Mitigation: T3 includes a DevTools spot-check on `npm run preview` confirming the computed `font-family` on a known element resolves to `Inter` after first paint; T5 (prod pass) repeats the check on the live site.
- **CDN cache poisoning via `immutable` on hashed assets:** Vite-hashed asset filenames (e.g. `index-BPebnIy2.js`) include a content hash, so an `immutable` Cache-Control on `/assets/*` is safe — a content change always changes the URL. Unhashed files (`ads.txt`, `robots.txt`, etc.) get only 86400-second (24h) max-age with no `immutable`, so updates propagate within a day. Mitigation: T2 acceptance criteria distinguish the two rule blocks; `immutable` only appears on `/assets/*`.
- **`ads.txt` cache lifetime impact on AdSense crawler:** AdSense re-reads `ads.txt` frequently; 24h cache is short enough to honor a publisher change within a day and long enough to satisfy Lighthouse's cache-lifetimes signal. Mitigation: chose 86400 s (24h) over 31536000 s for `ads.txt` explicitly; documented in T2 action.
- **`manifest.json` / `favicon.svg` / icon updates:** these change rarely and 24h is acceptable; if a future phase needs an aggressive purge, Cloudflare cache purge by URL still works regardless of Cache-Control. Mitigation: documented, no edit required.
- **AdSense consent gate / loader script:** untouched. `index.html` line 47–53 comment explicitly forbids re-adding a static AdSense `<script>` tag; this plan does not touch that block. Mitigation: T1 acceptance criteria grep for the comment block being present after the edit.
- **No new outbound network calls:** the font URL is the same `fonts.googleapis.com/css2?family=Inter:...` already in use. No new third-party host is introduced. No new dependency is added.
- **Cloudflare `_headers` precedence vs `wrangler.jsonc`:** Cloudflare Workers static-assets reads `_headers` from the configured assets directory and applies it to matched paths. The `wrangler.jsonc` `assets` block in this repo points at `dist/` (Vite output) by default, which after `vite build` contains the copied `public/_headers`. Mitigation: T2 action requires placing `_headers` in `public/` so Vite's static-asset copy step ships it into `dist/_headers`; T4 verifies via deployed-response Cache-Control headers (`curl -I https://currencyabout.com/assets/<hashed>.js`).

Severity ceiling: none at `high`. Proceed.
</threat_model>
