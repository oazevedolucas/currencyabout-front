<objective>
Audit the five in-scope pages (home, one long guide, one indexable pair such as USD-BRL, exchange-rates-today, methodology) at the locked iPhone 12/13/14 portrait baseline of 375x667, capture full-page screenshots and per-page issue lists into a new `02-MOBILE-AUDIT.md` artifact, verify the UX-06 fold-clearance condition for the `homeEditorial` ad slot via a measurement-first DevTools inspection before any code edit, apply surgical CSS-only fixes for any overflow, overlap, or cut-off-CTA defects flagged, spot-check the same five pages at 375 width in `de`, `zh`, and `ja` for locale-driven regressions, and confirm `npm run build` exits 0 with a final post-fix screenshot pass appended to the audit artifact.
</objective>

<must_haves>
- Mobile baseline is exactly 375x667 (iPhone 12/13/14 portrait, DPR 2). No other widths are audited or remediated in this plan.
- All five pages (`/`, `/guides/:slug` for the most-recently-updated guide, `/usd-brl`, `/exchange-rates-today`, `/methodology`) render with no horizontal scroll, no overlapping elements, and no cut-off CTAs at 375x667.
- UX-06 is verified measurement-first: the `homeEditorial` AdSlot is inspected for `offsetTop >= 667` BEFORE any layout edit; remediation only fires when measurement fails, and remediation is bounded to moving the AdSlot mount below the `<FAQ />` block in `src/pages/HomePage.jsx`.
- No new runtime or dev dependencies are introduced; existing palette, typography, and overall layout remain untouched (CLAUDE.md polish-only constraint).
- Locale spot-checks at 375 width are performed for `de` (longest strings), `zh`, and `ja` (highest information density) across the same five pages; any new defects feed back into the surgical-fix task.
- CSS fixes are surgical: at most one or two properties added per offending rule (typical: `min-width: 0`, `flex-wrap: wrap`, `max-width: 100%`, `word-break: break-word`, `overflow-wrap: anywhere`, `min-height: 44px` for tap targets). No component CSS rewrites; no new class hierarchies.
- `npm run build` exits 0 after every edit; `02-MOBILE-AUDIT.md` ends with a "Final pass: PASS" marker and final screenshot paths.
</must_haves>

<threat_model>
This plan is layout/CSS-only and does not touch user-controlled input, network, storage, or auth surfaces.

- **XSS / injection:** N/A. No user-controlled string is rendered or evaluated. No `dangerouslySetInnerHTML`, no `eval`, no new fetch calls.
- **Auth / authorization:** N/A. Site has no auth surface.
- **Data exposure:** N/A. No new storage keys, no new outbound calls, no AdSense behavioural change. The `useAdSenseLoader` consent gate and the `AdSlot` route allowlist remain unmodified.
- **Layout shift / CLS regression on home page:** real risk if T3 fires and moves the `homeEditorial` slot. Mitigation: Phase 3 will add a per-slot reserved `min-height` map; for this plan, the reservation is implicit (slot stays at its existing CSS width) and the move is a single JSX line reorder, not a CSS change.
- **Locale-driven overflow regressions:** moderate risk on `de` (longer strings) and `zh`/`ja` (denser glyphs). Mitigation: T5 explicitly spot-checks these three locales and folds any new defects into T4.
- **AdSense reviewer regression:** the plan touches a page (home) that is in active AdSense review. Mitigation: every edit must keep `npm run build` green; UX-06's measurement-first protocol ensures no speculative layout change is made.

Severity ceiling: none at `high`. Proceed.
</threat_model>
