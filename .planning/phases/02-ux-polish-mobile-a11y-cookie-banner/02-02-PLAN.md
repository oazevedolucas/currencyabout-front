<threat_model>
This plan touches a consent gate, ships a new script that performs outbound HTTP, and edits CSS tokens. ASVS L1 review:

- **AdSense consent bypass via the ESC handler:** the keyboard dismiss path must record `rejected` through the existing `decide()` function (which already persists to `localStorage` and dispatches the `cookie-consent-changed` event), not a direct `setVisible(false)` that hides the banner without recording a choice. A silent hide would re-show the banner next visit AND leave `useAdSenseLoader` in an inconsistent state. Mitigation: T-banner-jsx specifies `decide('rejected')` as the call target and verifies via an acceptance criterion that the `cookie-consent-changed` event fires exactly once on ESC.
- **Link-check script SSRF / arbitrary-URL abuse:** `scripts/link-check.mjs` performs outbound `fetch()` calls. If it accepted arbitrary URLs from CLI input, it could be repurposed to probe internal infrastructure from a developer machine or CI runner. Mitigation: the CLI accepts only the two-valued flag `--target prod|local`; the host is hard-coded to `https://currencyabout.com` or `http://localhost:5173` based on that flag, and the URL set itself is derived only from `public/sitemap.xml` and a grep of `src/` for internal `<Link to="..."` and `<a href="https://currencyabout.com/...">` references. The script's header comment documents this guard explicitly, and T-link-check-script's acceptance criteria require the header comment to be present.
- **XSS in banner copy or in the dark-token patch:** N/A. The banner copy is a static JSX literal with no `dangerouslySetInnerHTML`; the dark-token patch only adds CSS custom-property values and never touches DOM. Documented for completeness only.
- **Layout / regression risk during active AdSense review:** the banner card change is visible to a reviewer. Mitigation: every edit keeps `npm run build` green; the banner is gated on `getStoredConsent() === null` so an in-flight reviewer who already dismissed it will never see the new card; the `AdSlot` route allowlist and `useAdSenseLoader` consent gate stay byte-for-byte the same.

Severity ceiling: none at `high`. Proceed.
</threat_model>
